# git-worktree-pool

CLI (`git-wt-pool`) that manages a pool of reusable Git worktrees, so switching a slot to a new branch is fast (no fresh `npm install` / IDE re-index per branch). Standalone single-package repo. Depends only on Node built-ins + [`clipboardy`](https://github.com/sindresorhus/clipboardy). Node >= 22, npm >= 10.

## Commands

```bash
npm install                 # Install deps, set up husky hooks, build (via prepare)
npm run build               # Compile src/ to dist/ and add the shebang to the bin
npm run type-check          # tsc --build tsconfig.json (no emit)
npm run eslint              # Lint src/ and test/
npm run eslint-fix          # Auto-fix lint issues
npm run unit_test           # Run unit tests
npm run integration_test    # Run integration tests
npm run index-generator     # Regenerate the src/**/index.ts barrels (ctix)
npm run test-ci             # Jest with the jest-junit reporter (writes junit.xml)
```

Run a single test file: `npm test -- git-wt-pool.test`.

## Layout

```
src/bin/git-wt-pool.ts   <- entire CLI: arg parsing, repo/pool resolution, and all commands
src/bin/index.ts         <- auto-generated barrel (ctix) - do not edit
src/index.ts             <- auto-generated barrel (ctix) - do not edit
test/unit_test/          <- Jest unit tests (mirrors src/)
test/integration_test/   <- Jest integration tests
shell/gwt.{sh,ps1,cmd}   <- the "gwt" wrappers users install (shipped via "files" in package.json)
scripts/ensureHusky.js   <- installs husky hooks, also inside git worktrees
```

Tool configs at the root: `tsconfig.json` (type-check, `noEmit`), `tsconfig.build.json` (emits `src/` to `dist/`), `jest.config.ts`, `.eslintrc.json` (extends `.eslintrc.base.json`, `.eslintrc.typescript.json`, `.eslint.style.json`), `.ctirc`, `.husky/pre-commit`.

All logic lives in the single `git-wt-pool.ts` file. The `main()` switch dispatches to `cmd*` functions.

## Conventions

- Code style (enforced by ESLint): 4-space indent (2 more inside `switch` cases), double quotes, semicolons, stroustrup braces, max line length 200, no `console` in `src/` (allowed in `test/`), `import type` for type-only imports, no default exports.
- `src/index.ts` and `src/bin/index.ts` are generated by ctix. Do not edit them. After you add a source file, run `npm run index-generator`. The husky pre-commit hook runs it when a `.ts` file changed and stages the barrels.
- Tests: Jest 30 with `ts-jest`. Test files match `*.test.ts` or `*Test.ts`. Coverage reporters: `text` and `cobertura`.
- TypeScript: extends `@tsconfig/node22` with `target: es6`, `strict: false`, declarations on.

## Commands & aliases

`list` (alias `ls`), `assign`, `free`, `remove`, `path`, `init`. The switch lowercases the command; `list` and `ls` share a `case` and call `cmdList`. Add new aliases by stacking `case` labels. `init` is exempt from the wrapper gate and handled before `resolvePool()`, because it is how a user without the wrapper (and outside any repo) installs it.

## Gotchas

- A slot's free/assigned state is tracked by an **external** `.free-<slotname>` marker file in the pool root (sibling of the slot dir), not inside the worktree - keeps it out of `git status`. See `markerPath`/`isFree`/`markFree`/`markAssigned`.
- The marker is **not** zero-byte any more: `markFree` writes a `FreeNote` JSON (when it was freed, the branch it was on, and how to restore any work that was stashed or parked). `readFreeNote` reads it defensively, because markers written by older versions are zero-byte and must still count as free. `isFree` still only tests existence.
- `assign` copies the assigned worktree path to the clipboard (`copyToClipboard(assignedSlot)`) and prints "Path copied to clipboard." - so callers don't need a follow-up `path` lookup.
- Errors and warnings go to `stderr` (`console.error`). Progress lines from `assign`, `free` and `remove` go to `stdout`, and so does the output of the git commands they run with `stdio: "inherit"`, so stdout of `assign` is not a machine channel. `path` prints only the path on `stdout`.
- The machine channel is `--cwd-file <file>`: `assign` and `path` write the target path there (`writeCwdFile`); no other command touches it. A child process cannot change the parent shell's cwd, so the wrappers in `shell/` call the CLI with `--cwd-file` and `cd` to the file content from inside the shell. `gwt.sh` must be sourced (a file on PATH runs as a child process) and refuses to be executed; `gwt.ps1` and `gwt.cmd` work as files on PATH because PowerShell scripts and batch files run in the caller's session. `gwt.cmd` uses the `endlocal & cd /d "%TARGET%"` idiom so the `cd` survives `setlocal`. `.gitattributes` pins `gwt.sh`/`gwt.ps1` to LF and `gwt.cmd` to CRLF; the unit test checks this. Edit `gwt.cmd` with a CRLF-aware tool (or re-run `sed -i 's/\r*$/\r/'`); an editor that silently converts it to LF makes that test fail.
- **The wrapper gate.** Every wrapper sets `GIT_WT_POOL_WRAPPER=1` (`WRAPPER_ENV`) for the child process only. `main()` runs `needsWrapperSetup(command, process.env, process.stdin.isTTY)` right after `--help` and before the "no command" usage: at an interactive prompt without the variable it prints a two-line pointer to `git-wt-pool init` (`printWrapperRequired`) to stderr and exits 1, so the plain CLI cannot be used by hand once the wrapper exists, and a bare `git-wt-pool` shows that pointer rather than the usage. `init`, `--help` (exit 0), and any non-TTY caller (scripts, CI, hooks, agents) pass through.
- **`init` writes outside the package, so it confirms first and is idempotent** (`cmdInit`, driven by an injected `InitContext` so the tests control platform, env, home and TTY). PowerShell/cmd: `chooseInstallDir` proposes npm's global bin dir derived from `SHELL_DIR` (`<prefix>` on Windows, `<prefix>/bin` elsewhere) when it is on PATH, otherwise asks for a pasted directory (`~` expanded; a warning and a second confirmation when it is not on PATH) - PATH is deliberately not listed, it can hold dozens of entries; then `copyFileSync`. Prompts go through one `createPrompter()` readline interface per `init` run, which buffers lines that arrive between questions (piped stdin delivers everything at once) and aborts with exit 1 on EOF. bash/zsh: copies `gwt.sh` to `~/.config/git-wt-pool/gwt.sh` (`POSIX_WRAPPER_HOME_PATH`) and appends `source "$HOME/.config/git-wt-pool/gwt.sh"` to the chosen profile unless the profile already mentions that path; the copy is sourced, not the install dir, so nvm version switches do not break it. `init --print`, or a non-TTY stdin, only prints `renderShellSetup` and never writes. `SHELL_DIR` is `path.join(__dirname, "..", "..", "shell")`, which is the package root's `shell/` both from `dist/bin` and, under ts-jest, from `src/bin`.
- **Shell detection** (`detectShell`, pure; `detectCurrentShell` feeds it) slims the setup text to one shell. The parent process name wins (`parentProcessName`: `tasklist` on Windows at ~300 ms, `/proc/<ppid>/comm` on Linux, `ps -o comm=` elsewhere; only the setup path pays for it). Environment markers are the fallback because children inherit them: `MSYSTEM`/`SHELL` mean Git Bash, a `PSModulePath` entry under `USERPROFILE` means PowerShell (pwsh and 5.1 prepend it, cmd.exe does not), `SHELL` gives bash/zsh off Windows. Through npm's sh shim the parent is `sh.exe`, because MSYS `exec` cannot replace the process. `init <name>` (`parseShellKind`, accepts `pwsh`/`sh`) bypasses detection; `init --print --all` prints every block and omits cmd.exe off Windows.
- `printList`, `parseSlotStatus`, `isClean`, `slotStatus`, `pickFreeSlot`, `readFreeNote`, `cmdAssign`, `cmdFree`, `cmdRemove`, `cmdPath`, `cmdInit`, `WRAPPER_ENV`, `SHELL_KINDS`, `POSIX_WRAPPER_HOME_PATH`, `needsWrapperSetup`, `parseShellKind`, `detectShell`, `renderShellSetup` and their types are exported for the unit test; everything else is module-private. These flow out through the ctix barrel, so treat them as public surface.

## Cleanliness invariant (the reason this package has real tests)

A slot handed out by `assign` must be clean. Two git behaviours make that easy to get wrong, and both were verified empirically:

- `git diff --quiet HEAD` exits 0 for a tree that holds only **untracked** files. The old `hasDiff` used it, so `free` released such a slot with no warning and the next `assign` destroyed the files with `git clean -fd`. Cleanliness now comes from `git status --porcelain` via `parseSlotStatus`, which reports tracked and untracked separately.
- `git checkout <branch>` on a dirty tree exits **0** and carries the changes across, still staged, whenever the dirty paths are identical in HEAD and in the target branch. So the checkout exit code proves nothing. `cmdAssign` therefore checks the slot before the checkout (a free slot with tracked changes is skipped, and the next clean one is used) and re-checks after it.

`free` never abandons work: `--force` stashes it, and the interactive path offers stash, a `wip/` branch, abort, or a discard that needs a second confirmation and is unreachable under `-y`.

## The stash stack is shared

`refs/stash` is shared by the main checkout and every pool slot, and concurrent sessions push to it. So `stashSlotWork` pushes with a unique label (`git-wt-pool <slot> <branch> <timestamp>`), resolves that entry's SHA through `git stash list --format="%H %gs"`, and records the SHA. Restore is always `git stash apply <sha>`. Never use bare `git stash`, `git stash pop`, or `stash@{0}` here - the index is not stable.

## Tests

`test/unit_test/bin/git-wt-pool.test.ts` covers `printList`, `parseSlotStatus`, the bundled `shell/` wrappers (present, call `--cwd-file`, correct line endings - read through `jest.requireActual("node:fs")` because `node:fs` is mocked), the wrapper gate (`needsWrapperSetup` for wrapped / direct / non-TTY / `shell`, and the paths printed by `renderShellSetup` in detected and `--all` form), shell detection (`detectShell` with parent-process, inherited-marker and fallback cases; `parseShellKind` aliases), `cmdInit` (npm-dir default, candidate list, not-on-PATH warning, posix copy + idempotent source line, `--print`/non-TTY writes nothing), the `--cwd-file` writes of `cmdAssign` and `cmdPath`, and the `cmdAssign` / `cmdFree` / `cmdRemove` guard paths. `node:child_process`, `node:fs`, `node:readline/promises` and `clipboardy` are mocked: a `porcelain` map keyed by slot dir feeds `git status --porcelain`, and the fake also models `git clean -fd` removing untracked entries, so the post-checkout re-check sees a realistic tree. `process.exit` is mocked to throw, so a refusal is asserted with `rejects.toThrow("process.exit(1)")`.
